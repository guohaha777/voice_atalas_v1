# 声音规则 `@wanwu-v2/sound-rules`

孩子在声音诞生里点的五项（高低、长短、变化、轻响、出现方式），怎样变成听得到的声音，全由这个包决定。前端预览和以后的后端渲染读的是同一份规则，结果不会对不上。

- **数值**在 `rules/*.json`。音乐角色只需要改这里，不用碰代码。
- **算法**在 `src/`，都是纯函数：输入采样或体检结果，输出数据。
- **发声**在网页的 `apps/web/src/shared/audio/renderShaped.ts`，它只执行“塑形计划”，本身不带任何数值。
- 全程不用模型、不用联网。原始录音只读，从不改写。

## 两步：先体检，再按卡片塑形

1. **声音体检**（`src/analysis.ts`，规则 `rules/analysis.v2.json`）：每段录音算一次，结果是 `SoundAnalysis`，类型在 `@wanwu-v2/contracts/sound`。
   - **先找单个声音**：先按静音把录音分成一段段；超过 `units.splitAboveSeconds` 的长段，再在明显的音量低谷处（落下又升起 `splitDipDb` 以上）切开。这样鸟群里的一声声鸟叫也能找到。
   - **分三类**（`kind.*`）：
     - **单个声音** `one`：总长不超过 `oneMaxSeconds`，并且只有一声，或者最响的一声比第二响的高出 `oneDominanceDb`。
     - **一串声音** `series`：声与声之间安静的时间占比不低于 `seriesQuietRatio`。
     - **连成一片** `texture`：其余情况。
   - **还会测量**：一声的典型长度（中位数），以及它落在短 / 中 / 长哪一档（`unitLength.*`）；平均响度和峰值；偏高、居中还是偏低（`brightness.*`）。
2. **塑形**（`src/shaping.ts`、`src/arrange.ts`，规则 `rules/shaping.v3.json`）：
   - 纸卡前四问是**描述**孩子当时听到的样子，所以往卡片描述的样子靠：已经在那一档就不动。
   - 第五问“你希望它怎么出现”是孩子的**意愿**，照做。
   - 每一项都作用在**单个声音**上；同一项在三类声音上的做法不同（见下表）。
   - **不在一声的中间一刀切**：只在两声之间切；不得不缩短时用较长的渐弱（`edges.cutFadePortion`）；连成一片的声音前后都留淡入淡出（`edges.textureFadeSeconds`）。

| 维度 | 单个声音 / 一串声音 | 连成一片 | 主要参数 |
| --- | --- | --- | --- |
| 高低 | 原声已在那一档就不动；差一档移 `semitonesPerStep` 个半音（不超过 `maxSemitones`），同时调亮或调暗。只变调，不变长短 | 同左 | `pitch.*` |
| 长短 = **一声有多长（时值）** | 每一声拉长或缩短，每差一档乘或除以 `stretchPerStep`（限制在 `minStretch`–`maxStretch`），音高不变、不剪。每一声仍在原来的时刻出现（不改节奏），拉长后撞上下一声时，下一声才往后让 | 整片放慢或加快（`textureMinStretch`–`textureMaxStretch`），每一声跟着变长或变短 | `duration.*` |
| 变化 | 在**每一声里**往上滑 / 往下落 `contour.unit.bendCents`，同时由闷变亮或由亮变闷；有起伏 = 较快的颤动（`contour.unit.wave`） | 在整段上变化，同时越来越近（`rampDb`）或越来越远；有起伏 = 缓慢的涌动（`contour.texture.wave`） | `contour.*` |
| 轻响 | 先统一响度（`targetRmsDb`、`maxBoostDb`、`peakCeilingDb`），再分三档 `choiceDb`，配合起音快慢和明暗 | 同左 | `level.*`、`intensityTone.*` |
| 出现方式 = **这些声音怎么排** | 出现一次 = 原来的样子。重复 = 最响的那一声按固定节拍出现 `count` 次。一阵一阵 = 声音自己的几声组成一组（`hitsPerGroup`），组与组之间停 `groupGapSeconds`。慢慢出现 = 一声比一声响（`seriesFromDb`）；单个声音则在这一声里慢慢淡入 | 重复 = 均匀地涌来退去 `count` 次（`waveSeconds`）；一阵一阵 = 像阵风（`gustSeconds`）；慢慢出现 = 渐强 | `pattern.*` |

**选了却没变化时要告诉孩子**：`unchangedBy()` 会判断两种情况。一种是原声本来就是那样（高低、长短落在同一档）；另一种是这个选项本身就是“保持原样”（稳稳的、刚刚好响、出现一次）。声音诞生页会让向导小鸟说出来，例如“它本来就是「短短的」，所以听起来没怎么变”。

**时长**：听到多长由同一条时间线决定（`arrange()`）。它只依据孩子的选择、片段，以及这个声音单元自己带着的体检结果（`SoundUnitDraft.analysis`），所以声场尾条、成曲曲谱和实际渲染一定一致，测试里逐一核对过。声音诞生交出的声音单元、声音库示例都带着体检结果；示例声音的体检结果在生成声音库时算好（`npm run assets:library`）。

在声场里，孩子“剪一剪”出来的片段就是要用的那一段。刚放进声场时，默认是去掉前后静音的整段，孩子再自己剪。

## 改规则的流程（给音乐角色）

1. 打开 `rules/shaping.v3.json` 或 `rules/analysis.v2.json`，改数值。每个数值的含义见上表；允许范围在 `src/schema.ts`。
2. 运行 `npm test`。填错了（超出范围、拼错名字、短比长还长、轻响三档没有从小到大）会直接报中文错误并指出是哪一项，**不会上到网页**。
3. 用固定的测试声音集逐个维度、逐档听一遍，确认没有把别的声音调坏。

> 遇到问题按现象查对应参数。例如：
> - “一阵一阵太密” → `pattern.bursts.groupGapSeconds`
> - “鸟鸣该算一串声音” → `analysis.kind.seriesQuietRatio` 或 `units.splitDipDb`
> - “长长的不够长” → `duration.stretchPerStep` / `maxStretch`
> - “往上走听不出来” → `contour.unit.bendCents`
> - 改了体检规则（`analysis.v2.json`）后，要运行 `npm run assets:library` 重算示例声音的体检结果，否则检查会报错。

### 调音台（**尚未开发**，以下是已定的规则）

**它是什么**：给音乐角色用的规则调试工具，用来**定通用规则**，不是给某一段声音单独调。用户（老师、孩子）接触不到它。

**日常使用全部自动**：
- 老师或孩子上传、录音之后，系统自动做声音体检：找出单个声音，分成单个声音 / 一串声音 / 连成一片，统一响度，判断高低。
- 孩子在五个维度上点选，系统按同一套规则自动塑形。
- 整个过程没有人工环节，也不用模型。

**页面要做到**：
1. 只在开发环境（`npm run dev`）或特意开启的预览构建里出现，**正式站不打包**。实现上用动态导入，并由 `import.meta.env.DEV` 或一个预览开关（例如 `VITE_ENABLE_LAB=1`）控制，路由例如 `/lab/sound-rules`。
2. 选一段示例声音、测试声音集里的声音，或上传一段，看到体检结果：主体段在哪、找到的单个声音（画在波形上）、分类、一声多长、偏高 / 居中 / 偏低、响度。
3. 逐个点五个维度的每一档，和原声来回对比。用的就是正式页面的 `planCard` / `planClip` + `renderShaped`，只是把规则对象换成页面上正在调的那份（这些函数都已经接受 `rules` 参数）。
4. 每个参数一个滑块，范围取自 `src/schema.ts`，拖动后马上重渲染并试听。滑块旁边写参数名和 README 里的说明。
5. 一键导出 `analysis.v*.json` / `shaping.v*.json`，导出前先跑同一套范围和关系校验，不合格就不让导出；放进 `rules/` 就生效，不用改其他文件。改了体检规则的，还要运行 `npm run assets:library` 重算示例声音的体检结果。

**测试声音集（回归集）**：
- 上线前准备 15–20 段有代表性的声音：鸟叫、滴水、流水、风、蝉、蛙、人声、敲击、车声、掌声等，三类声音都要有。
- 原件放 `assets-source/audio/test-set/`（不进 `public/`），清单放 `docs/assets/test-set.json`（名称、来源、许可、预期分类）。
- 音乐角色在调音台里用这组声音，把每个维度、每一档都听一遍，调到“大多数声音都合适”，然后导出规则文件。调的是“短短的有多短”“一阵一阵间隔多少”这类通用数值。
- 以后每次改规则，都用同一组声音再听一遍，确认没把别的声音调坏；工作量固定，不随上传数量增加。可以再加一个自动检查：测试集每段的预期分类写进清单，`npm test` 对比体检结果。

**发现问题时怎么定位**：每个参数都有名字，本 README 有对应说明。例如觉得“一阵一阵太密”，就对应 `pattern.bursts.groupGapSeconds`；只改这一个数，页面代码和其他维度都不受影响。

**上线后**：
- 发现某一类声音普遍听着不对，比如很短的敲击声做“长长的”总是怪，就改对应的那条通用规则，所有声音一起生效；听感变了就另存新版本文件。
- 体检认不出声音（整段都是静音或杂音，`SoundAnalysis.silent`），声音诞生页应自动提示“这段好像没录到声音，可以重录”，不需要人工处理。**这条提示还没做**：现在静音录音会被当作原声保留，塑形不出错，但不会提醒。

## 版本

- 规则文件名带版本：`shaping.v3.json`、`analysis.v2.json`。上线前的旧草案（`shaping.v2`、`analysis.v1`）没有保存过任何作品，已直接替换。每份文件的 `version` 字段会写进塑形计划和体检结果。
- **上线前**调数值不改版本号，因为还没有保存过的作品。
- **上线后**，任何会改变听感的修改都另存为新版本文件，旧文件保留；作品记录自己用的规则版本，旧作品按原规则重放。这一步在接后端时一起落实。
- 体检结果的类型 `SoundAnalysis` 带有 `rules` 字段。后端可以把它和声源一起保存，体检规则变了再重算。目前网页按缓冲区现算并缓存（`apps/web/src/shared/audio/soundAnalysis.ts`）。

## 已知待调

- 当前数值是草案，只做过数值测量和渲染检查，**还没有用耳机 / 外放实听**。
- 示例里，鸟鸣、蝉鸣、苹果落地、风吹树叶、自行车都被判成“偏高”。这些录音本身高频成分多，分档界线需要用测试声音集来定。
- 峰值很尖的声音（例如滴水），“响亮的”和“刚刚好”音量接近，差别主要来自起音和明暗。整体限幅属于混音规则，后续在 `mix` 里处理。
- 声音卡试听最长 10 秒。连成一片的长声音（鸟鸣、蝉鸣）在试听里只听前 10 秒左右，在声场里按孩子剪的片段完整播放。
