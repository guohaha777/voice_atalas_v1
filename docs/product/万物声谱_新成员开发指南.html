总览：这一版是什么

万物声谱让乡村低年级孩子用纸笔记录听见的声音，老师用一部手机录入，系统把声音编排成一首短曲，并用孩子听得懂的话讲出来。10 月底这一版是放在公开的 H5 网页上的完整流程体验版，为后面进入公益组织的学校做准备。整体结构图见第 08 节。

本版要做到
  • 国内手机和电脑能直接打开网址，走完整条流程
  • 老师用手机浏览器（H5）现场录音，音源库里能看到并使用
  • 公共音源库：任何人可上传，孩子在校园端调用
  • 班级、学校、地域共享音源和曲子
  • 新板块：课本音乐接入创作
本版不做，留到下一阶段
  • 信息保护细则、同意流程
  • 内容审核机制
  • 本地小模型、离线缓存（PWA）
  • 复杂的班级管理后台、数据看板
  • 多个教材版本、音频导出
  • 微信小程序（待定，不排期）
不能动的原则
  • 孩子的原声永远是主角，原始录音不覆盖
  • AI 不替孩子做决定，只在后台降低门槛
  • 每个 AI 环节都有不联网的降级方案
  • 来源如实标注，本地方案不冒充模型

10/30 上线标准

  • 老师用手机浏览器（H5）录音，音源库里能看到并使用

项目可调节文件

调整 AI 和音乐的表现，改的是下面三类文件，不需要动页面和接口。路径相对仓库根目录。

A · 提示词存储

给模型的文字指令，集中在 src/prompts/，一个模型任务一个文件。纯文本，不会写代码也能改。

B · 声音规律分析

把孩子的选择和编排算成数字与规则，相近的输入得到相近的结果。它既直接驱动本地方案，也生成提示词里的参数。

C · 混音与配置

响度、版本号、模型地址和密钥。响度要用手机外放听过才能定。

04

会用到的模型

两类模型，都通过服务端调用。密钥只在服务端环境变量里，浏览器代码和仓库里都不能出现。

千问 · 语言模型

阿里云百炼，OpenAI 兼容接口

  • 当前配置：qwen3.7-flash-2026-07-15（见 .env.example）
  • 任务：作品理解与音乐小发现、智能音符 Plan B；本版新增课本讲解润色
  • 输入：匿名的音乐结构摘要，不含录音、姓名、照片、地点
  • 输出：严格 JSON，经 zod 校验；格式问题由程序修补
  • 失败时：本地规则生成同类内容，来源标为 local_fallback
  • 接口：app/api/composition/advice/route.ts、app/api/music/plan/route.ts
Fun-Music · 音乐模型

阿里云百炼，模型名 fun-music-preview

  • 任务：生成无人声、无歌词的纯音乐背景垫音
  • 输入：由作品摘要推出的一段文字描述。它听不到孩子的声音，只按描述生成
  • 输出：mp3 和一个会过期的临时链接，必须转存到自己的对象存储
  • 入口限制：邀测权限；单访客限频 3 次、同一访客同时只允许 1 个请求、单实例每日 30 次、超时 180 秒
  • 失败时：由用户选重试、千问智能音符，或只听儿童声音
  • 接口：app/api/music/generate/route.ts
接手前要知道：背景音乐目前默认走的是本机 ACE-Step，不是 Fun-Music

src/app/CompositionRoot.tsx 里背景生成器现在创建的是 AceStepPolishGenerator，它请求本机 127.0.0.1:8001，权重约 14GB，只能在开发者电脑上跑，能听到孩子的混音。FunMusicPolishGenerator 和云端接口代码已经写好，但不在默认路径上，也还没有用真实密钥跑通。本版要把默认切到 Fun-Music，并保留“千问智能音符 → 本地动态音符 → 只听儿童声音”的降级链。上线前先确认 Fun-Music 的邀测权限和额度，没有就以智能音符为本版背景。

主链路不靠网络，也不靠 AI

从听到基础成曲全在本地。AI 只出现在三处：背景音乐、作品讲解、课本讲解润色，每处都有降级。

降级链路

Fun-Music → 千问智能音符 → 本地动态音符 → 只听儿童声音。界面写明这次用的是哪一种。

弱网要做的三件事

录音先存手机再补传；上传带进度并自动重试；用过的音源缓存在本机，课前可预下载；模型请求设短超时，失败立即降级。

如果本地部署小模型，不联网也能用 AI 吗？

部分可以。文字类 AI 可以，音乐音频生成不行。而且主流程本来就不需要 AI：没有网络时，系统用本地规则完成全流程，只是少了模型写的内容。

AI 任务本地小模型结论
作品理解、音乐小发现
课本讲解润色
智能音符动机（短 JSON）		任务短、输出是固定格式，1B–4B 量级的小模型有机会胜任。现有的校验和修补仍然适用。低年级措辞的质量需要实测，不能假设和千问一样可以，需实测
背景音乐音频音频生成模型体积大、要显卡。本机 ACE-Step 权重约 14GB，手机和电子黑板跑不了不可行

两种部署方式

  • 校内一台电脑或小主机（Ollama、llama.cpp 等提供 OpenAI 兼容接口）。局域网内可用，不需要外网。适合下一阶段
  • 浏览器或手机里直接跑（WebGPU）。首次要下载数百 MB 到 1GB 以上，低端设备和电子黑板不稳定。不建议

代码上要改的地方

  • 千问接口本来就是 OpenAI 兼容格式，换成本地小模型只改 COMPOSITION_ADVISOR_* 三个变量
  • app/api/music/plan/route.ts 里的 isPublicHttpsEndpoint 会拒绝本机和内网地址，要加一个受控的开关

本版建议：不做本地小模型，保持云端千问加本地规则兜底。接口已经留好，等拿到真实学校的网络条件，再决定要不要做校内小主机。

06

新板块：把课本音乐纳入创作

新增

让师生先从熟悉的课本走近万物声谱，再慢慢走向自由创作。后台的做法是：用代码和 AI 自动读出课本曲子的特征，存成一份固定的特征模板；孩子编排完以后，系统把这个特征换几种说法、放进背景里，让孩子听出“这首歌的特点，和我排的声音碰在一起会发生什么”。

特征提取：交给代码和 AI，不靠人工标注

可以做到。分工原则是：数值交给代码，语义交给 AI。语言模型读不准速度和音高，这类数字由音频分析库算；情绪、性格和给孩子的那句话才交给 AI 写。

特征怎么提取可靠度常见误差
速度、拍号节拍跟踪（librosa、essentia 等开源库）；有电子谱时直接读取高可能快一倍或慢一半
节奏型起音检测，按拍量化，找出现最多的 2–4 拍组合中伴奏多时起音会混杂；有电子谱则精确
疏密、力度走向每秒起音数、响度曲线高—
音区、明暗音高分布，加频谱重心（也就是“频率”的那一面）中多声部时会偏
调式、主音调性估计（五声、大调、小调）中大调和小调容易混
重复与段落自相似矩阵中—
情绪、性格、一句话千问：根据上面的数值写，或用百炼上的音频理解模型听一遍再写（可用型号要先确认）主观只作描述，不作数值来源
怎样把对专业度的要求降到最低
  • 优先拿电子谱（MusicXML 或 MIDI）：代码直接读，速度、节奏、音高都是精确的。只有谱面图片时可先用识谱工具转换，准确率要实测
  • 只有音频也能做：用上表的方法提取，并给每项打一个置信度
  • 核对只靠耳朵，不需要乐理：核对页会叠加提取出的节拍音，问“拍子对得上吗？”，选“对 / 快一倍 / 慢一半”；再问“这句话像不像这首歌”。置信度低的项才会提醒看一眼
  • 特征提取脚本放在 tools/textbook-features/，输出 public/textbook/tracks-v1.json
版权与存储
  • 音频或谱面只在开发机上读取，不进仓库，不上云
  • 模板里只有特征和出处（版本、页码、曲名）
  • 有了自动提取，曲目数量不再受人工限制，首批仍建议 8–12 首，方便先把效果验证清楚
  • 课本曲目能不能这样用，需要公益组织确认

特征模板：每首曲子一张卡

{
  "id": "tb-g1-u3-01",            // 示例，非真实曲目
  "source": { "edition": "人音版", "grade": 1,
              "unit": 3, "title": "（曲名）" },
  "tempoBpm": 100,

  "onsetDensity": "medium",       // sparse | medium | busy
  "pitchRange": { "low": 60, "high": 72 }, // MIDI 音高
  "brightness": "mid",            // 频谱重心：暗 | 中 | 亮
  "mode": "pentatonic",
  "dynamics": "soft-to-medium",
  "repetition": "high",
  "mood": "lively",

模板字段用在哪里
tempoBpm meter背景速度；Fun-Music 描述词里的 BPM
rhythmCell动机的时值序列（motifBeats），变奏的原料
pitchRange brightness mode背景音区、明暗和调式（derivePitchMaterial）
onsetDensity repetition和孩子编排的疏密对比，写进讲解
dynamics mood能量与情绪方向
childLine讲解里“这首曲子像……”那一句
extraction记录哪些由代码、哪些由 AI 产生，以及是否听过核对

套用：不是照搬，而是换几种说法

背景用到的是模板的相似版本，由程序变奏、再由 AI 润色。目的是让孩子看到：一首歌的特征可以有不同的表达形式，而每一种和自己的编排碰在一起，都会有不一样的反应。

① 观察特征

先让孩子注意到这首歌的一个特征，比如“长—短短—长”的节奏，或“一小段一小段”的疏密。一次只讲一个。

② 不同的表达形式

程序对节奏型做变奏：原样、拉长（扩张）、压短（紧缩）、错开半拍、换到高音区或低音区。其中扩张、紧缩、倒影在 developMusicIdea.ts 里已有，错开和换音区按同样方式补上。AI 再把每种变化润色成孩子的话。孩子在“原型 / 变化一 / 变化二”之间切换对比听。

③ 和我的编排碰在一起

程序比较背景的节奏点和孩子声音出现的位置，归成三种反应：对齐（一起用力）、错开（一问一答）、填空（补在孩子的空隙里）。讲解里说出这次发生了哪一种。新增

讲解示例

孩子把雨滴声排成“一阵一阵、轻轻的”，系统匹配到一首节奏轻快的课本歌曲：

“这首歌的特点是一小段一小段地走。我们把它拉长了一点，背景听起来变得很悠闲。你的雨声一阵阵落下，正好落在背景的空隙里，像在和它一问一答。试试把雨声挪到前面，听听它们会不会撞在一起。”

结构固定为：特征 → 这次的表达 → 和你的编排发生了什么 → 一个能马上试的小任务。沿用现有约束：不用专业术语，不评价孩子。

匹配与三档路径

匹配：规则算相似度，本地完成

孩子的作品摘要和模板用同一套字段：速度、疏密、重复方式、音区、情绪。加权求和排序，取前 3 首，每首带一句“为什么像”。老师指定了本周曲目时排第一。权重放在配置文件（建议 public/textbook/match-weights.json）里，方便调。

三档路径：从课本走向自由

① 跟着课本：老师先选本课曲目，页面先讲它的特征，孩子再编排。
② 系统帮你找：孩子自由编排，系统挑最像的 3 首并解释。
③ 自由创作：不选课本，就是现有流程。老师新建采集活动时可以绑定本周曲目，网页默认从 ① 开始。

接入点（建议路径，均为新增）
  • tools/textbook-features/：提取脚本和听感核对页
  • src/domain/textbook/：模板类型与校验
  • src/features/textbook-match/：匹配、变奏、碰撞类型
  • public/textbook/tracks-v1.json：特征模板
  • src/prompts/textbookExplainPrompt.ts：讲解和变奏润色
  • 在 buildMusicPolishBrief 加可选字段 textbookReference，随作品保存
  • 成曲页加“课本模式”面板，可切换原型和两种变化
边界与验收
  • 背景借节奏和气质，不复制课本旋律
  • 提取验收：每首曲子的速度、节奏型用耳朵核对通过，置信度低于阈值的必须过一遍
  • 匹配回测：每首曲子造 2–3 组“应该匹配到它”的编排，看是否进前 3
  • 孩子能否从中听出特征、比较不同表达，是设计目标，还没有课堂验证

音源怎么进入孩子的创作

现有声音来源是系统声音、历史声音、本次录音三种，本版增加第四种：音源库。孩子选中一段音源，仍按纸卡的五个维度（高低、长短、变化、轻响、出现方式）塑造，原始音频不改，参数另存。之后进入声场编排和成曲，流程不变。

和现有代码的关系

浏览器本地库（Dexie，见 src/storage/db/WanwuDatabase.ts）已有音频资产、声卡、声音单元、作品、贡献者等表，云端基本沿用，不重新设计。云端实现挂在 src/features/ports/ 的仓库接口后面，页面不直接访问存储。本地继续作为缓存和待上传队列，用过的音源会留在本机，下次不联网也能用。

本版和下一阶段

信息保护和审核机制放在下一阶段，所以本版上传后直接进库，按测试数据处理，可能整批清理。上传页给一句提示，字段上不收孩子的真实姓名、人脸照片和精确位置，只留昵称和大致地点。授权记录、监护人同意、内容审核、保存期限和删除入口在下一阶段设计，但数据表里先留出“可见范围”和“来源”字段，后面不用迁移。

产品形态：H5 网页

web 端决定用 H5 网页：手机、电脑、电子黑板的浏览器里直接打开，微信里也能用。老师带孩子在现场用手机录音，回到课堂在电子黑板上展示，作为课堂内容。微信小程序方案待定，不在这一版排期内。

系统一张图：一套 H5，一个云端，两类模型

H5 · 手机

老师的手机 · 校园现场

  • 打开：链接或二维码，微信里也能用，不用安装
  • 做：登录、选班级、建采集活动（可绑课本曲目）、录音（≤30 秒，可试听重录）、填名称昵称地点、上传、看音源库
  • 弱网：录音先存手机（IndexedDB），有网自动补传。页面要先加载完，目前没有离线缓存
  • 可选：拍纸卡读取
  • 技术要点：微信内置浏览器要在 iOS 和安卓真机上验证，重点是麦克风录音权限、音频必须由点击触发才能播放、Web Audio 的兼容；录音格式因系统而异，需要统一或在服务端转码
H5 · 课堂

电子黑板 · 电脑

  • 形态：一套响应式 H5，手机竖屏、电脑和电子黑板横屏共用一个页面，更新后立刻生效
  • 做：完整创作流程、音源库、班级与共享浏览、课本模式、作品墙
  • 课堂展示：全屏、大字、触控目标放大；时间线放大，播放到哪个声音就高亮哪个；孩子上台点选和摆放
  • 访客：免登录可用示例声音走完全程，数据只存本机
  • 技术要点：横屏适配，要在真实电子黑板上测浏览器版本
设备谁在哪用主要做什么联网
手机浏览器（含微信内）老师，校园现场登录、录音、填信息、上传、看音源库录音不需要，上传需要
电子黑板老师和孩子，课堂上完整创作、音源库、作品墙、课本模式页面加载后基础创作不需要，同步和音源库需要
电脑老师，办公室备课、整理音源、预览作品同上

微信小程序：待定，不纳入本次排期

原设想是作为老师的手机入口，用来现场录音和上传。是否做、什么时候做，等测试版的反馈和主体、备案条件明确后再定。本版先用 H5 承担现场采集，数据格式和接口按“以后可以接小程序”的方式设计，不另做开发。
